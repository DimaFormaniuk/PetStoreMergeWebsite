2. The game and website

Pet Store Merge is a mobile merge game in which players combine pet-store items, discover upgraded items, and complete orders for animal customers. The website is a static information site hosted using Cloudflare Pages according to its README.

The project includes gameplay progression, local saves, remote configuration and mailbox content, local notifications, advertising code, in-app-purchase code, optional platform cloud saves, analytics and crash diagnostics, and promo-code functionality. A feature can vary by platform, region, build, consent choice, network availability, and remote configuration.

3. Availability and changes

The game downloads remote configuration, app-version data, mailbox configuration, and related content from the project's HTTPS configuration host. The current private configuration enables mailbox loading and lists cloud progress, promo-code, store, daily-task, and notification-related feature flags.

The project does not promise uninterrupted availability, a particular feature set, compatibility with every device, or a specific update schedule. Maintenance, version changes, regional limitations, and discontinuation terms must be confirmed by the operator.

4. Progress, platform accounts, and cloud saves

The repositories do not show a custom Pet Store Merge username, password, or account-registration flow. Progress is stored locally and may be synchronized through platform-specific services: Google Play Games Saved Games in an Android player build or iCloud Key-Value Store in an iOS player build. Other platforms use the project's unavailable-cloud-save path.

The project also contains an optional cloud progress snapshot service that posts serialized progress to api.secontalcompani.com with a device token header. The current remote configuration lists a 300-second minimum interval and 20 successful uploads per UTC day. The exact production activation and data-retention terms must be verified.

Because the repository does not define a user-facing account deletion or guaranteed recovery process, players should not treat cloud synchronization as a promise that every item of progress can always be restored.

6. Purchases and virtual content

The Unity project contains an in-app-purchasing integration and a purchase-restore path. The checked BaseSettings asset selects simulated purchases for the current project configuration, while real Unity IAP paths are present in code. This repository therefore does not prove which products or prices are offered in a store build.

The game model contains in-game currencies and items, including USD, Coin, Energy, board items, shop content, and rewards. The repositories do not establish that virtual content is transferable, redeemable for cash, or refundable by the operator. Prices, taxes, subscriptions, billing, refunds, restoration, and the effect of service changes must follow the applicable store rules and be documented by the operator.

7. Advertising and consent

The project contains AppLovin MAX rewarded and interstitial advertising code, ad-result events, and a consent-flow configuration. The checked project settings select simulated ads, so the repository alone cannot establish that live ads are served in a particular release or identify every mediation partner.

On iOS the project requests App Tracking Transparency authorization when the status is undetermined. Consent behavior, personalized-ad choices, and the providers active in each region must be confirmed for the production build. The related privacy details are described in the Privacy Policy review copy.

8. Promo codes and external content

Remote mailbox content can include text, images, and external actions. Following an external action opens a destination outside the game. The operator should identify and approve those destinations and their terms before publication.
