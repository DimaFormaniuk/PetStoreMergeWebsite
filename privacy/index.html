Privacy Policy

Review copy - not yet ready to be treated as a complete legal notice. This page records behavior confirmed in the current website and game repositories. The publication questions at the end must be answered and the text must receive legal review before release.

Last updated: 27 August 2026

1. Scope and project identity

This review copy concerns Pet Store Merge, a casual mobile merge game, and the static website that presents information about it. The website repository identifies the project name as "Pet Store Merge" and the project company name as "SeConTalCompany." The repository does not establish whether that name is a complete legal entity name.

The website is configured for secontalcompani.com. This page does not make a claim about the controller, data-protection officer, registered office, or governing jurisdiction because those details are not verified in the repositories.

2. The static website

The website files are static HTML and CSS. The repository contains no first-party account form, contact form, login, comments, or first-party analytics script. The site links to the home page, this policy, the terms page, and mobile-store listings. A visitor who follows an external link is subject to that provider's own privacy notice and terms.

The README says that the site is hosted using Cloudflare Pages. The repository does not document the host's request-log configuration, retention, cookie behavior, or any processor terms, so those details must be confirmed separately.

3. Data handled by the game code

The following categories are supported by code or configuration in the current Unity project. Their availability can vary by platform, build, remote configuration, consent choice, and whether a service is enabled in a released build.

  • Device and app information. The game reads Unity's SystemInfo.deviceUniqueIdentifier. The current code uses it as the Firebase Analytics user ID, as the AppLovin MAX user ID when that service is active, and as an X-Device-Token header for cloud-progress and promo-code requests. App version and platform are also included in saved progress and analytics-related events.
  • Gameplay and usage events. The game sends Firebase Analytics events through its event adapter. Confirmed event families include tutorial steps, level-ups, completed or replaced orders, shop and ad outcomes, energy purchases, fortune-wheel activity, daily-task rewards, promo-code use, ratings, and purchase or restore actions. Some events include gameplay, product, level, platform, or result values.
  • Crash and diagnostic information. Firebase Crashlytics is initialized by the project, and the code enables reporting uncaught exceptions as fatal. The repository does not define the complete diagnostic fields retained by Firebase.
  • Local game state. Progress is stored locally through Unity preferences. The model includes level and experience, in-game currencies, board and item state, orders, shop state, settings, tutorial state, mailbox collection, promo-code history, rating state, daily tasks, advertising counters, fortune-wheel state, play time, game counters, user/app counters, and purchase restoration or pending-confirmation state.
  • Cloud progress. When enabled by configuration, a JSON progress snapshot contains the cloud-save schema version, save time, total play time, app version, platform, and the player-progress model described above. The snapshot is posted over HTTPS to the configured cloud API with the device token header.
  • Promo-code requests. The current private remote configuration enables the promo-code interface and selects a Cloudflare backend. A claim request sends the entered promo code to the cloud API together with the device token header. The repository does not show an email, name, or custom account field in that request.
  • Notification settings. On Android and iOS the game requests operating-system notification permission and schedules local "energy full" reminders when the in-game notification setting is enabled. The code shown here schedules local notifications; it does not establish a remote push-message database or a remote push-token workflow.

4. Services and integrations visible in the repository

The project contains code or package configuration for the following services and platform features:

  • Firebase Analytics and Firebase Crashlytics;
  • AppLovin MAX advertising and its consent-flow configuration;
  • Unity In-App Purchasing;
  • Google Play Games Saved Games on Android player builds;
  • iCloud Key-Value Store synchronization on iOS player builds;
  • the project's HTTPS cloud API at api.secontalcompani.com for optional progress snapshots and promo claims;
  • HTTPS remote configuration, app-version data, mailbox text, and mailbox images served from secontalcompani.com/config/; and
  • Unity mobile-notifications APIs for local reminders.

The checked BaseSettings asset selects simulated ads and simulated purchases for the current project configuration. The code also contains real AppLovin and Unity IAP paths. Therefore the repository alone cannot prove which integrations are active in every store build or which advertising mediation partners are used.

5. Purposes supported by the implementation

Based on the code, the listed information can be used to operate and secure game features, synchronize progress, validate promo claims, deliver remote configuration and mailbox content, measure gameplay and ad or purchase outcomes, diagnose crashes, support consent flows, and schedule local reminders. The repositories do not establish that data is sold, shared for targeted advertising, or used for any purpose outside these implementation paths.

6. Network transfers and sharing

The game makes HTTPS requests for remote configuration, app-version information, mailbox configuration or content, cloud progress, and promo-code claims. Cloud progress and promo requests include the device token header; cloud progress also includes the serialized progress snapshot. Firebase and AppLovin SDKs receive information through their SDK APIs when those integrations are active.

Google Play Games and iCloud can process saved-game data when their platform-specific cloud-save paths are available and the player is authenticated or has a supported Apple ID/build. The exact provider roles, regions, sub-processors, international-transfer terms, and retention periods are not specified in this repository.

7. Remote configuration and upload limits

The private remote configuration committed for the current project lists cloud progress as enabled, with a minimum upload interval of 300 seconds and a maximum of 20 successful uploads per UTC day. It also lists remote mailbox loading as enabled. These values are configuration evidence, not a promise that every released build uses them; the production configuration must be checked before publication.

The code requires HTTPS for accepted remote configuration and cloud API URLs. This describes transport and input validation in the code; it is not a guarantee of any provider's security or of a particular retention period.

8. Storage, retention, and deletion

The repository does not define a user-facing retention schedule, deletion request process, or provider-specific deletion guarantees. Local progress and settings are written to device storage through Unity preferences. Cloud-save, analytics, crash, advertising, purchase, and platform-account retention is controlled in part by the applicable service and platform configuration and must be documented from those systems before publication.

The repository contains no verified in-game personal-data deletion or access-request workflow. Do not infer a retention period from the upload interval or from the local save format.

9. Choices and controls visible in the project

Players can use platform controls for notification permission and, on iOS, the App Tracking Transparency prompt requested by the game when tracking status is undetermined. The project also contains AppLovin consent-flow settings. The precise consent choices, withdrawal behavior, personalized-ad settings, and regional rights process are not fully represented in this website repository.

Turning off a platform permission or removing local app data may affect features, but the project does not define the legal effect of those actions or a guaranteed deletion result.
